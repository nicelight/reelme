# linux_digiCamControl

Локальный Python-сервер для тестирования ReelMe на Linux вместо digiCamControl.
USB-фотоаппараты — через gPhoto2; системные веб-камеры — через V4L2/FFmpeg.
Реализована нужная часть HTTP API, **не вся программа digiCamControl**.

## Запуск на Ubuntu / Kubuntu / Debian

```bash
sudo apt install python3 gphoto2 ffmpeg v4l-utils
cd linux_digiCamControl
python3 linux_digicamcontrol.py
```

Выберите номер камеры в терминале. Откройте:

```text
http://localhost:5513/reelme-test.html
```

Нажмите **«Запустить тест»**. Один запуск = три фотографии. Повтор — только кнопкой.
На V4L2 при запуске теста в большом окне включается живое зеркальное превью.
Во время отсчёта оно продолжает обновляться; каждый полученный оригинальный JPEG
показывается без зеркалирования 0,5 с, затем возвращается превью. После трёх кадров
страница отправляет файлы обратно на локальный сервер и сравнивает SHA-256.
В интернет ничего не отправляется. Полученные при тестовой загрузке байты не сохраняются.

Превью включается только после «Запустить тест» и останавливается после серии,
при ошибке или уходе со страницы. Если preview недоступен, страница явно сообщает
об этом и продолжает съёмку без него; уже полученные фото сохраняются в галерее.
Для gPhoto2/mock и Windows digiCamControl остаётся прежний сценарий без preview.
Для отдельной диагностики потока доступна **http://localhost:5513/liveview.html**.
CaptureClient ReelMe использует те же API-маршруты автоматически.

**Остановка:** Ctrl+C. **Фото и логи:** `data/session-…/`.
Для смены камеры остановите сервер и запустите его снова.

## Другие варианты

```bash
# Список устройств и их ID
python3 linux_digicamcontrol.py list
python3 linux_digicamcontrol.py list --json

# Выбор без меню
python3 linux_digicamcontrol.py serve --camera /dev/video0 --open-browser
python3 linux_digicamcontrol.py serve --camera gphoto2:usb:001,007

# Параметры веб-камеры; размер/формат должны поддерживаться устройством
python3 linux_digicamcontrol.py serve --camera /dev/video0 --size 1280x720 --input-format mjpeg

# Без оборудования и дополнительных пакетов — только синтетические JPEG
python3 linux_digicamcontrol.py serve --camera mock
```

USB-порт в примере условный: используйте ID из `list`. Порт меняется при переподключении.
Физические камеры никогда не подменяются демонстрационной автоматически.

## Если не снимает

- Закройте приложения, использующие камеру: OBS, Cheese, браузерный видеозвонок,
  импорт фотографий, другие экземпляры сервера. Фотоаппарат не должен быть открыт
  в файловом менеджере как камера/накопитель.
- На фотоаппарате выберите одиночный кадр и JPEG либо RAW+JPEG. Для Canon разумная
  исходная настройка — P + Auto ISO; сервер сам параметры не меняет.
- При `Permission denied` проверьте `ls -l /dev/video*` и `id`.
  Права на конкретное устройство настраиваются средствами дистрибутива; запускать
  весь сервер через `sudo` или выдавать `chmod 777` не требуется.
- Форматы веб-камеры: `v4l2-ctl -d /dev/video0 --list-formats-ext`.
  Без `--size`, `--fps` и `--input-format` используются настройки по умолчанию драйвера.
- Журнал сервера: `data/session-…/server.log`; на странице — «Скачать логи для Сергея».

Python **3.10+**, без зависимостей pip. Сервер слушает только `127.0.0.1`.
Live View поддержан только для V4L2: один FFmpeg получает кадры для превью и съёмки.
После команды Capture/LiveView_Capture сохраняется следующий кадр потока.
Превью хранится в памяти, без накопления файлов; `/preview.jpg` по-прежнему возвращает
последнюю сохранённую фотографию. Stop освобождает камеру; без запросов превью/съёмки
15 секунд поток также останавливается. Обычный Capture после остановки работает.
У gPhoto2 и mock Live View не поддержан (HTTP 501). Запись видео и камеры,
доступные только через libcamera/PipeWire, не реализованы. Нужен обычный V4L2 capture-узел либо поддержка съёмки в gPhoto2.
