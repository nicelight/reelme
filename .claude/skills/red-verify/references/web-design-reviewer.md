# Semantic pack: web-design-reviewer

Use rendered observation when an accessible UI, relevant route, browser tool,
and safe state can materially strengthen the requested verification. Otherwise
choose sufficient available evidence and state any real limitation.

Inspect only concerns grounded in the accepted outcome and actual change:
responsive layout, reachable loading/error/success states, keyboard access,
labels/contrast, touch use, visual consistency, and stability may be useful.
These are possibilities, not a mandatory checklist or new acceptance criteria.

A finding identifies the route/state, relevant viewport, reproduction, expected
and observed behavior, material impact, and redacted evidence. Use available
project tooling; no particular browser runner or screenshot report is required.
The calling skill owns its verdict, permissions, and evidence locations.
