# TASK-004 — результат реализации

2026-11-14. Локальная съёмка соединена с серверным приёмом JPEG, finalize, номером и освобождением установки.

## Изменения

- Sessions сохраняет оригинал в уникальный приватный файл, проверяет JPEG/размер/декодирование, затем в короткой SQLite-транзакции повторно проверяет capturing и записывает одну позицию. Большие записи и декодирование находятся вне транзакций. Замена одной позиции не затрагивает остальные; после finalize записи закрыты.
- GET возвращает CaptureStatus, PUT принимает multipart file, finalize проверяет полный набор 1/4 и один раз меняет capturing → submit_pending. Повтор возвращает текущее состояние. Ключ установки обязателен для всех трёх операций; CORS допускает localhost:5513.
- PhotoSession хранит снятые Blob до завершения передачи. Повтор отправляет нужный Blob/позицию, без камеры; принятые позиции определяются сервером. Только finalized показывает «Ищи свое видео под номером NNN на промо экране». Следующий посетитель очищает sessionStorage/локальное состояние и открывает каталог без ожидания генерации.
- После reload состояние читается с сервера: уже принятые позиции пропускаются, завершённый приём возвращает прежний номер. Ещё не переданные Blob не восстанавливаются из браузерного хранилища.

API-проверки: полный/неполный набор; повтор позиции с сохранением остальных; один переход при concurrent finalize (SQLite audit trigger в тесте); после finalize PUT=409 и файлы неизменны. Реальный поток HTTP upload, начатый до finalize, завершается отказом 409 после закрытия сессии; принятый файл сохраняется, SQL-транзакция не удерживается при записи потока. Дата/номер/план, записи и JPEG сохраняются после restart.

Фактический доступ: GET/PUT/finalize без ключа или с неверным bearer — 401, с admin/operator cookie без installation — 403. Localhost preflight — 204, разрешены PUT/Authorization/Content-Type; сторонний origin не получает Access-Control-Allow-Origin. Неверные JPEG/индексы — 400; неизвестный sessionId — 404; oversized JPEG — 413. Неудачная загрузка не меняет уже принятый файл.

Browser-проход: Recast (1) и модель с 4 позами, разные sessionId/номера и пять различимых JPEG в правильных позициях. Между посетителями использована реальная кнопка, без fixture reset/reload. 503 при загрузке → тот же объект Blob и байты, без нового затвора; предыдущая позиция и файл неизменны. Потерянное подтверждение finalize восстанавливается через GET, номер скрыт до подтверждения. После перезапуска backend оба набора сохранены.
