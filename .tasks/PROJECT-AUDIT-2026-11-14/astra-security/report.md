## Выполненные проверки

### Независимый сквозной probe

Команда из корня проекта:

```sh
node --import tsx .tasks/PROJECT-AUDIT-2026-11-14/astra-security/probe.ts
```

Результат: **PASS**. [Исходник](probe.ts), [наблюдения](probe.log).

Probe создаёт временную SQLite/медиа через штатный test fixture для первоначальных аккаунтов. Затем все изменения слотов, capture-сессий, фото, email и удаление мероприятия идут через реальные HTTP handlers; progression выполняют настоящие workers с явно подменёнными внешними транспортами. Прямых изменений domain-state в БД — 0; БД читается для проверки фактов и issued capabilities. Видео создано локальным FFmpeg, принимается и декодируется кодом приложения.

Проверены:

- Шесть конкурентных одинаковых start дают одну сессию и один `201`; шесть finalize сохраняют одно `submit_pending`.
- Изменённый после старта слот не меняет исходный prompt/референс первой сессии. Provider URL выдаёт байты старого материала.
- Три одновременных `runOnce` делают один submit; после остановки worker и рестарта приложения наблюдается сохранённый ID. Первый download падает, второй использует тот же результат: submit 1, status 1, download 2.
- Receive/download/provider-токены не взаимозаменяемы и не являются учётными данными аккаунта/установки; session UUID и номер не открывают форму; каталог файлов не опубликован.
- Неверный bearer вместе с валидной admin-cookie возвращает `401`; admin не становится установкой/оператором; чужой Origin запрещает изменение, чужой CORS origin не получает разрешающего заголовка. Каталог не раскрывает generation input.
- Пять конкурентных подтверждений email принимают ровно одно письмо. Потеря SMTP-ответа даёт failed, дальнейший worker pass не отправляет повтор; явный исправленный email разрешён. После sent повтор получает `409`.
- Первый email timestamp сохраняется при повторе; в `179999 ms` строка видна, в `180000 ms` скрыта. Полный email отсутствует; receive остаётся доступным после скрытия.
- API запрещает удаление сегодняшнего дня. Удаление прошлого дня закрывает receive/download/provider/capture URL, удаляет directory и session row, очищает заменённый материал. Следующая сессия, её фото и текущий материал слота остаются доступны.

## Ограничения

- Только локальные временные БД/файлы; production-данные и рабочие учётные данные не использовались. Тестовые каталоги удалены fixture cleanup.
- fal и отправка/удаление внешних данных полностью подменены. Локальный SMTP тестового сервера не доказывает доставку SMTP.BZ. Совместимость с живыми endpoint, фактический CDN deletion и особенности тарифа не проверены; оператор исключил обязательные live fal/SMTP проверки.
- Модельные входы сопоставлены с принятой `.memory-bank/analysis/fal-api.md`; отдельное актуальное исследование внешних API не проводилось.
- Windows/Canon/digiCamControl, production deployment, TASK-005, физическая съёмка и художественное качество не входят в verdict. Browser UI проверяет второй независимый аудитор; этот отчёт не заявляет собственного browser-прогона.
- Отдельные проверки не распространяются на неописанную многопроцессную эксплуатацию: принят один серверный процесс с SQLite и in-process workers.
