## Границы и зависимости

TASK-003 требует только основу TASK-001: экран можно проверить с фиксированным
планом поз в тестовом запуске, не дожидаясь каталога/старта TASK-002.
Нужная начальная настройка digiCamControl уже дана в
[контракте камеры](../../.memory-bank/contracts/integrations.md#камера-digicamcontrol);
он задаёт ответы тестового стенда при разработке. Реальная настройка и испытание
перенесены в TASK-005 по решению оператора.

TASK-004 обоснованно зависит от TASK-002 и TASK-003: связывает реальную сессию
с кадрами, добавляет приём файлов и завершение съёмки. Дата, номер и снимок
используются из FT-001. Граница генерации — сохранённый `submit_pending`;
работающий fal не нужен для проверки того, что интерфейс освобождается.
Фактический submit остаётся в FT-003, симуляция не представляется реальной генерацией.

TASK-005 оправдана настройкой конкретного окружения и AC-004. Она включает
конфигурацию Caddy/systemd, установку, облачное обновление и все аппаратные проверки
AC-001–004 после завершения разработки приложения. Во время разработки те же
пользовательские сценарии проверяются на стенде; это разные условия доказательства.
Обратных зависимостей от TASK-005 нет. При добавлении задач остальных функций
её prerequisites нужно дополнить конечными задачами разработки, как указано в карточке.
Три задачи имеют самостоятельные результаты; дополнительное деление не требуется.

## Проверки и условия исполнения

Три карточки прошли JSON Schema Draft 2020-12; ID, tier/wave/feature и индекс
согласованы. Пути/якоря разрешаются, все четыре AC представлены. Зависимости
существуют, циклов нет; Production acceptance является конечной задачей.
`git diff --check` — без ошибок. Все задачи planned, `verify` пуст;
команды `gates` будут взяты из созданного приложения, вымышленных PASS нет.

Доступ к Windows/Canon не нужен для разработки TASK-003/004: используются
управляемые ответы digiCamControl, а загрузка/SQLite проверяются на реальном backend.
При успешных проверках разработки допустим done_for_prod с оставшейся приёмкой
TASK-005; это не блокирует зависимые задачи. Симуляция не считается PASS камеры.
Выбранный VPS, доступ к домену и целевой установке нужны TASK-005 после завершения
разработки приложения. Проверки на боевом оборудовании до этого не планируются.

Решение о сроке аппаратных проверок принято оператором. Выполнять TASK-003 после
TASK-001, затем TASK-004 после TASK-002/003. TASK-005 оставить до конца разработки.
Дополнительные задачи и отдельный круг ревью не нужны.
