## Реализация

- `generation_jobs` сохраняет fal request ID/URLs, выходной URL, ошибки и проверенные
  локальные файлы. Worker в одном Fastify-процессе восстанавливает состояния после
  рестарта; подтверждённый ID никогда не отправляется повторно. Capture HTTP не ждёт fal.
- Recast получает video URL, одно фото и разрешение сохранённого снимка, без prompt.
  `@fal-ai/client` 1.10.1 оставляет retries включёнными, отключает fallback, задаёт
  Store-IO:0 и CDN expiration 86400. HTTP-отказ submit отличается от потери подтверждения.
- Provider URL относится к одному материалу Scenarios либо принятому фото сессии;
  токен стабилен для неизменного файла. Замена материала не ломает снимок старой сессии.
  Обычные защищённые медиа/админка не становятся публичными.
- Результат скачивается потоком, проходит ffprobe и полный FFmpeg decode, затем
  извлекается JPEG. Байты пишутся вне SQL-транзакции. Проверенный файл не скачивается
  заново после рестарта; сессия остаётся `preparing` до TASK-008.
- Терминальные/непригодные результаты дают `failed`, временные сетевые сбои повторяют
  текущий шаг. Фото и сессия сохраняются. Capture-state содержит безопасный error;
  подробности серверного лога очищены от ключа, URL и токенов. URL запросов редактируются
  логгером. README и `.env.example` описывают включение, состояния и ограничения.

FFmpeg; только fal/download transport управляемый. [Наблюдения](generation-observations.json)

Видео 320×240, 5 секунд, 3039 байт; извлечён JPEG 674 байта. Сессия A сохранила прежний
материал/768P; B/C используют новый материал/1080P и одинаковый provider URL.

временный polling, явный 422, COMPLETED с ошибкой, terminal result HTTP, временное
скачивание + restart preparing (один submit, один result, два download), пустой и
повреждённый файл. После ошибок фото остаются; ready не возникает. SDK-тест сверяет
payload/headers и отсутствие CDN upload, отдельный тест — очистку ошибок от секретов.

обслуживаться; следующий посетитель может начать сессию.
