# Техдолг ReelMe · 20 ноября 2026

Выборочный аудит ревизии `d80d913` охватил съёмку, редактор сюжетов, генерацию и выдачу, хранение медиа и мониторинг. Пункты упорядочены по ожидаемой отдаче. Затраты — оценка работы одного разработчика с целевой регрессионной проверкой.

1. **Переключатель видимости может потерять правки или оставить старый сюжет в каталоге. Высокая отдача, 2–4 ч.** Для изменения одного флага клиент отправляет весь сюжет из ранее загруженного списка. Если во второй вкладке уже поменяли промпт, первая запишет старую версию. У старого сюжета Gemini с сохранённым разрешением `4k` локально подтвердился другой эффект — попытка скрыть его вернула HTTP 400 из-за проверки разрешения. Исправление — отдельная операция, которая меняет только `visible` в текущей записи. [Переключатель](src/client/cloud/App.svelte#L121) · [Сохранение](src/server/scenarios/index.ts#L55)

2. **Сборщик теряет историю измерений контейнера на каждом опросе. Высокая отдача, до 1 ч.** Замер записывается под полным Docker ID из `inspect`, а для следующего цикла сохраняются ключи с коротким ID из `docker ps -aq`. В локальной проверке двух циклов с такими ID оба значения `cpu_percent` оказались `null`. Выборочный максимум памяти также каждый раз начинается заново, хотя накопленное CPU-время и пик памяти от ядра продолжают читаться. Достаточно использовать полный ID в обоих местах. [Ключ замера](deploy/observe.py#L56) · [Фильтрация истории](deploy/observe.py#L108)

3. **Удалённая фотосессия запирает съёмочную вкладку на кнопке «Повторить». Высокая отдача, 2–4 ч.** После удаления мероприятия сервер отвечает `404 NOT_FOUND`. Установка показывает ошибку связи, а после перезагрузки восстанавливает тот же ID из `sessionStorage`. Для подтверждённого отсутствия сессии стоит дать явный выход в каталог. Если в памяти ещё есть снятые JPEG, переход должен предупреждать об их потере. [Ответ сервера](src/server/sessions/index.ts#L55) · [Обработка и кнопка](src/client/capture/PhotoSession.svelte#L55) · [Восстановление вкладки](src/client/capture/App.svelte#L89)

4. **Окончательно недоступный ролик остаётся «в подготовке». Высокая отдача, 2–4 ч.** Загрузчик превращает любой неуспешный HTTP-ответ в обычную ошибку, и worker повторяет скачивание по сохранённому URL. В локальной проверке два прохода с HTTP 410 дали два скачивания и тот же статус `preparing / GENERATION_RETRY`. Платный запрос генерации при этом не повторяется. Стоит передавать HTTP-статус обработчику, завершать сессию при 410 и сохранить повтор при временном сетевом сбое. [Загрузка](src/server/sessions/video.ts#L28) · [Обработка и повтор](src/server/sessions/generation.ts#L157)

5. **Исправный MP4 получает окончательный статус ошибки при сбое публикации. Средне-высокая отдача, 3–6 ч.** Проверка медиа и запись QR находятся в одном `catch`, который помечает результат как повреждённый. На подготовленном ролике временная недоступность FFmpeg дала `failed / INVALID_RESULT`. После восстановления FFmpeg повторный вызов пропустил сессию из-за её статуса. Стоит различить повреждение файла и сбой окружения, записывать причину в серверный журнал и повторять только публикацию с ограниченной частотой. [Проверка и смена статуса](src/server/sessions/receive.ts#L50)

6. **Отмена редактирования оставляет загруженные материалы на диске. Отдача зависит от объёма, 1–2 ч на подсчёт, 1–2 дня на безопасную очистку.** Файл и строка SQLite создаются до сохранения сюжета. Очистка мероприятия рассматривает только ID из снимков конфигурации его сессий, поэтому загрузка из брошенного черновика туда никогда не попадёт. Повторный импорт шаблона тоже создаёт отдельную копию. Сначала стоит посчитать байты без ссылок. При существенном объёме — очищать старые кандидаты с учётом открытых черновиков и повторной проверкой ссылок из сюжетов, сессий и образцов ракурсов. [Загрузка](src/server/scenarios/media.ts#L64) · [Импорт](src/server/scenarios/templates.ts#L27) · [Отбор кандидатов](src/server/sessions/cleanup.ts#L29)

7. **Запрет записи в хранилище браузера блокирует кнопку тестовой генерации. Низкая отдача, до 1 ч.** Компонент выставляет `posting=true` и сохраняет ID до входа в `try/finally`. Если `sessionStorage.setItem` выбросит исключение, первый POST ещё не отправлен, а кнопка уже останется выключенной. Стоит обработать запись внутри защищённого блока и показать причину. Сохранять ID до отправки важно для безопасного повтора платного теста. [Сохранение ID](src/client/cloud/SlotTest.svelte#L29) · [Запуск теста](src/client/cloud/SlotTest.svelte#L72)
