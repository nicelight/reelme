# Прямое управление Canon EOS 1100D из браузера

**Предложение для ReelMe.** Отдельная страница `/cam-test-web` должна ответить на два вопроса. С какой частотой и задержкой посетитель видит себя в Live View? Можно ли надёжно получить полноразмерный JPEG после одного спуска, в том числе после краткой занятости камеры? По итогам испытаний можно решить, подходит ли WebUSB для будущего камерного адаптера.

## Что можно проверить на Kubuntu

Один и тот же клиент работает по цепочке «Chrome/Edge → WebUSB → USB-камера». Команды камеры формирует libgphoto2, собранная в WebAssembly внутри web-gphoto2. Архивированный репозиторий содержит готовые JS и WASM. В проверенном бинарном файле есть записи `Canon:EOS 1100D` и `Canon:Rebel T3`. Это основание попробовать именно этот комплект. Доступность спуска и превью проверяется после подключения через `getSupportedOps()`, работоспособность — получением реальных кадров. [Проверенная ревизия ec3f446](https://github.com/GoogleChromeLabs/web-gphoto2/tree/ec3f4462b1f4c58ecb0e9411bbddb2ab8a5ccea8)

На Kubuntu можно собрать страницу, проверить загрузку WASM и его рабочего потока, изоляцию, состояния интерфейса и повтор после ошибок. Если подсоединить EOS 1100D к Linux-компьютеру, можно испытать тот же браузерный код с реальным USB без Windows VM. Потребуются права на устройство и свободный USB-интерфейс. При осмотре стенда Canon не была подключена. Встроенная веб-камера использует другой протокол. На Windows 11 остаётся отдельная проверка привязки драйвера, переподключения и длительной работы на компьютере фотобудки. [Опыт автора порта на разных ОС](https://web.dev/articles/porting-libusb-to-webusb#important-cross-platform-compatibility-notes)

## Что увидит оператор

На одном экране расположены выбор USB-камеры, подключение и отключение, запуск и остановка Live View, кнопка снимка, состояние соединения и фактический FPS. Диалог выбора открывается по клику. Для первого опыта подключена одна камера: публичный `showPicker()` запрашивает разрешение, а `connect()` не принимает выбранный экземпляр устройства. Короткие сообщения различают отмену выбора, отсутствие доступа, занятость камеры, обрыв связи и неопределённый результат спуска. [Реализация браузерного API](https://github.com/GoogleChromeLabs/web-gphoto2/blob/ec3f4462b1f4c58ecb0e9411bbddb2ab8a5ccea8/src/camera.ts)

Камера настроена на JPEG. Страница хранит в памяти вкладки пять последних полученных оригиналов, показывает маленькие превью и позволяет повторно скачать каждый файл. При добавлении шестого снимка страница освобождает ресурсы старейшего. Размер изображения для показа сохраняет пропорции и укладывается в 800×600. Эксперимент обходится без создания фотосессии ReelMe, отправки кадров на сервер и установки ключа фотобудки.

## Ограничение при получении оригинала

`captureImageAsFile()` вызывает спуск, получает путь на камере и читает оригинал. При выходе из блока код пытается удалить файл по этому пути. Очистка возможна и после ошибки чтения. Браузер получает готовый `File` только в конце. Публичный API не выдаёт путь для отдельного повтора чтения. [Исходный код захвата](https://github.com/GoogleChromeLabs/web-gphoto2/blob/ec3f4462b1f4c58ecb0e9411bbddb2ab8a5ccea8/src/api.cpp#L151-L187)

Для первого испытания кнопка «Снять» инициирует один вызов. Если файл уже в браузере, «Скачать» повторяет сохранение этого файла. Если вызов оборвался после возможного спуска, страница сообщает «Снимок мог быть сделан, оригинал не получен» и сохраняет этот исход в результатах испытания. Только явная команда «Снять новый кадр» инициирует следующую экспозицию. Если для рабочего адаптера потребуется именно дочитывать потерянный оригинал, понадобится изменить WASM-обёртку: разделить спуск и чтение, сохранить идентификатор файла и пересмотреть момент удаления.

## Live View и освобождение камеры

Одновременно выполняется одна USB-операция. Цикл запрашивает следующий `capturePreviewAsBlob()` после обработки предыдущего кадра. При спуске или остановке страница прекращает планировать запросы и дожидается активного. После съёмки превью возобновляется, если оператор оставил его включённым. При краткой занятости допустим ограниченный повтор чтения превью. Остановка цикла в браузере и выход камеры из режима видоискателя проверяются раздельно. При отключении завершаются цикл и активная операция, затем вызывается `disconnect()`. В обёртке этот метод удаляет контекст вне очереди. Просроченный таймер сам по себе не подтверждает отмену USB-операции. Успешное повторное подключение и возврат камеры другой программе проверяются отдельно. [Код очереди и отключения](https://github.com/GoogleChromeLabs/web-gphoto2/blob/ec3f4462b1f4c58ecb0e9411bbddb2ab8a5ccea8/src/camera.ts)

## Доставка страницы

Для теста достаточно отдельной HTML-точки входа Vite и точечного маршрута раздачи. Пакет фиксируется по версии или ревизии. Его `camera.js`, `libapi.mjs` и `libapi.wasm` раздаются с того же домена с сохранением относительных путей. Загрузчик находит WASM относительно `import.meta.url`, а `libapi.mjs` также запускается как module worker. Проверять нужно собранную страницу с корректными MIME для модуля и WASM. [Сборка библиотеки](https://github.com/GoogleChromeLabs/web-gphoto2/tree/ec3f4462b1f4c58ecb0e9411bbddb2ab8a5ccea8/build) · [Конфигурация ReelMe](../../vite.config.ts)

Боевой адрес использует HTTPS, локальная разработка возможна через localhost. Документ получает `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp`, выделенный скрипт worker также получает COEP. Перед выбором камеры проверяются `navigator.usb`, `crossOriginIsolated` и доступность `SharedArrayBuffer`. Область действия заголовков ограничена тестовым документом и его ресурсами. Маршруты облачной фотосессии и страница digiCamControl используют прежние правила. [Изоляция документа и workers](https://web.dev/articles/coop-coep)

## Драйвер Windows

Короткая памятка на странице предлагает сначала закрыть приложения, занявшие камеру, и попробовать подключение. Если требуется WinUSB, перед заменой записать текущий драйвер, сверить название и USB ID именно камеры в Zadig, убедиться, что запись исчезает при её отключении, и выбрать WinUSB только для нужного интерфейса. После замены digiCamControl может утратить доступ. Для возврата восстановить прежний драйвер камеры в диспетчере устройств, переподключить её и проверить пробный кадр в digiCamControl. Это отдельное изменение конфигурации Windows, которое изоляция тестовой страницы не устраняет. [WebUSB на Windows](https://developer.chrome.com/docs/capabilities/build-for-webusb#windows) · [Zadig](https://zadig.akeo.ie/)

## Как оценить результат

| Испытание | Что записать |
|---|---|
| Минута превью движущегося секундомера | Частота фактически показанных кадров, 95-й процентиль интервалов, самая длинная пауза. Ориентир — около 20 кадров/с. Для задержки снять одним внешним видео секундомер и его изображение на экране и сравнить показания. |
| Серия из десяти спусков во время Live View | Число намеренных спусков, число декодируемых оригиналов, размеры JPEG, время от спуска до файла и до следующего свежего кадра превью. |
| Остановка, обрыв USB, повторное подключение | Может ли браузер освободить и снова открыть камеру, что произошло с незавершённым снимком, остались ли доступны уже полученные пять оригиналов. Штатную паузу во время экспозиции учитывать отдельно. |

Результаты стоит записывать вместе с ОС, версией браузера, ревизией библиотеки и драйвером. При сравнении с digiCamControl использовать тот же компьютер, фотоаппарат и движущийся объект. Устойчивость связи оценивается дополнительно на длительном прогоне.
