# Последовательная настройка слотов — матрица

Поведение и трактовки лимитов согласованы с оператором. Неоднозначности документации
сохранены ниже с источниками; дополнительных ограничений для перестраховки нет.
Это целевое поведение интерфейса; его внедрение **ещё не завершено**.
[Машинная матрица](../../src/shared/slot-setup-matrix.json) и 813 готовых `.md`-промптов
уже сформированы: [каталог и правила выбора файла](prompt-catalog.md),
[функция выбора](../../src/shared/slot-prompt-selection.ts).
[План внедрения](../../.memory-bank/analysis/slot-setup-plan.md).
Детали API и первичные источники: [Kling O1/O3](../../.memory-bank/analysis/slot-setup-api/kling-o.md),
[Kling 4](../../.memory-bank/analysis/slot-setup-api/kling-v4.md), [MiniMax/Vidu/Gemini](../../.memory-bank/analysis/slot-setup-api/other-models.md).
Платных генераций и проверки доступа аккаунта не было.

## Принятые правила

- Настройка: режим → модель и её возможности → персонажи → кадры → параметры
  выходного видео → «Зафиксировать параметры генерации» → материалы, промпт, тесты.
- Персонажи: `1`, `2`, `3+`. Для 1/2 — равное число индивидуальных кадров, сначала
  все кадры первого, затем второго. Для 3+ — один набор групповых фото без Elements.
- В Kling один индивидуальный персонаж = один Element из 2–4 разных ракурсов;
  вариант 1 отключён. Для остальных P2V — 1–4 кадра; у Recast — один на человека.
- Elements — структура API, не распознавание/вырезание лиц приложением. Для моделей
  без неё UI пишет «Elements не поддерживаются», не выдумывает максимум людей.
- Нижние поля раскрываются после фиксации, верхние блокируются. Разблокировка
  очищает дополнительные референсы, правку промпта, демо и нижние настройки;
  тестовые фото остаются в кеше. Обложка/описание/видимость — карточка слота,
  не сбрасываемые генерационные материалы. Жёсткая привязка V2V-видео сохраняется.
- На верхней панели находятся также качество, ориентация, ratio и P2V-длительность.
  Смена верхнего параметра пересчитывает допустимые следующие варианты; сохраняет
  ещё допустимые значения, очищает недопустимые. Старый ручной промпт не переносится.
- Промпт берётся целиком из готового `.md` для выбранного setup и фактического
  количества references. Подстановок/сборки текста в runtime нет; одинаковые
  тексты разных вариантов могут храниться в отдельных файлах.
  Описание слота не используется; текстового AI inference нет. Пользователь правит
  весь итоговый текст. У Recast шаблон пустой, поле необязательно и редактируемо;
  предупреждение: **РЕКОМЕНДУЕТСЯ ОСТАВИТЬ ПРОМПТ ПУСТЫМ!**.
- Если после ручной правки меняются дополнительные references, текст сохраняется;
  показывается напоминание проверить ссылки. Если правок ещё нет, шаблон обновляется.
  Кнопка восстановления шаблона может явно заменить ручной текст. Предупреждение
  не запускает скрытую генерацию и не «исправляет» авторский текст.
- Тесты требуют отдельного фото на каждый кадр каждого человека/группы. Автокопий
  одного JPEG нет. Кеш сохраняется при смене setup; сложного восстановления после
  закрытия браузера не требуется. Байты не сохранять в localStorage.
- Снимок начатой фотосессии неизменен при правке слота, ролика или образцов поз.

## Матрица моделей, кадров и вместимости

`C` = 1 или 2 индивидуальных персонажа; `K` = кадров на человека/группу;
`R` = максимум дополнительных фото **сверх камеры**. `G` означает режим 3+.
В группе `E=0`, индивидуально Kling `E=C`, остальные не имеют Elements.
Число файлов камеры: `C×K` или `K` для группы. Нельзя вычитать фото внутри Element
из бюджета ordinary images; их нельзя повторно посылать в `image_urls`.

потолка к Flash не полностью раскрыты в fal; это не результат runtime-проверки.

Эта таблица задаёт все **108** вариантов «модель + персонажи + кадры»:
Recast 2; семь Kling по 10; три остальных P2V по 12. Выбор выходных параметров
образует произведение только с допустимыми строками следующей таблицы. Недопустимые
сочетания отключены; примерные лимиты из задания не приписываются конкретной модели.

С учётом каждого возможного количества дополнительных references от 0 до R
получаются **813 файлов**. JSON содержит все 108 строк съёмки и в каждой —
`promptFiles[фактическое количество дополнительных фото]`. Ссылки в таблице выше
открывают только примеры; полный выбор делается по JSON. Качество, ориентация и
длительность не меняют текст и не умножают набор файлов; это отдельные параметры API.

Под моделью показывать отдельно обычные изображения, Elements и ракурсы одного
Element. При max Elements >3 сохранять формат «доступно 3 (max N)»; это сводка
возможностей API, а не обещание трёх индивидуальных людей в текущем setup.
После выбора отдельно показать фактически используемые Elements и фото камеры.
У ordinary/group-пути фото камеры занимают позиции обычных изображений.

## Распределение и ошибка фиксации

Для плоского бюджета N: `A1=min(K,N)`, `A2=min(K,max(0,N−A1))`,
`R=max(0,N−A1−A2)`; у одного человека/группы второй набор отсутствует.
Для Kling применяется бюджет соответствующей строки, а не эта формула к сырым JPEG.

| Бюджет / выбор | Первый | Второй | Доп. фото | Фиксация |
|---|---|---|---|---|
| 5 фото; 2×4 | 4 | 1 | 0 (нет места) | Запрет |
| 12 фото; 2×4 | 4 | 4 | 4 | Разрешена |
| 2 фото; 2×4 | 2 | 0 (нет места) | 0 (нет места) | Запрет |
| 5 фото; 2×2 | 2 | 2 | 1 | Разрешена |
| O1/O3 V2V; 2×4 | 4 внутри Element1 | 4 внутри Element2 | 2 | Разрешена |
| H3 Reference; 2×4 | 4 | 4 | 1 | Разрешена |
| Gemini; 2×4 | 4 | 4 | 2 | Разрешена |

Текст называет модель, режим, доступный бюджет, фото каждого участника и остаток.
При неравенстве двух наборов попытка включить фиксацию выводит строго:
«выберите меньшее количество фотографий во время фотосессии.»
Ни одному человеку нельзя молча уменьшать выбранный план. Для текущих одиночных
вариантов K≤4 все допустимые минимумы/потолки соблюдены; при нарушении фиксация
отклоняется с указанием доступного количества. Сервер проверяет те же правила.

## Разрешение, ориентация и aspect ratio

Показывать только запрошенные уровни 720p/768p и 1080p; другие API-разрешения вне
этого UI. Для отсутствующего параметра показывать «Разрешение задаёт модель»,
не выдумывать выбираемое значение. Flash: 720p доступно, 1080p отключено с причиной.
Ориентации: горизонтальная и вертикальная. Ratio фильтруется по ориентации; если
вариант только один, он выбран явно. `auto`/`adaptive` не фиксируют направление;
квадрат 1:1 не входит в двухориентационный scope. Crop/upscale/поворот не добавляются.

| Модели | Значения resolution в API | Горизонтальная | Вертикальная |
|---|---|---|---|
| Recast | 768P / 1080P | По ролику, без aspect_ratio | По ролику, без aspect_ratio |
| Kling O1/O3 V2V | Поля нет | По ролику, без aspect_ratio | По ролику, без aspect_ratio |
| Kling O3 P2V | Поля нет | 16:9 | 9:16 |
| Kling 4 full V2V/P2V | 720p / 1080p | 16:9, 21:9 | 9:16 |
| Kling 4 Flash V2V | 720p | По ролику, без aspect_ratio | По ролику, без aspect_ratio |
| Kling 4 Flash P2V | 720p | 16:9, 21:9 | 9:16 |
| H3 Reference | 768P / 1080P | 16:9, 4:3, 21:9 | 9:16, 3:4 |
| Vidu Q4 | 720p / 1080p | 16:9, 4:3 | 9:16, 3:4 |
| Gemini Omni | 720p / 1080p | 16:9 | 9:16 |

«По ролику» не обещает независимую настройку выхода API: противоположное направление
недоступно без соответствующего исходника слота. Исходники и имена:
[media/template-videos](../../media/template-videos/readme_media.md). Плеер показывает
именно выбранный исходник. Файл не найден — явное отсутствие шаблона, без случайной
подстановки. MP4 можно выбрать с компьютера или импортировать из серверной папки
по указанному имени. Оба способа проверяют ориентацию и ограничения модели.
Каждая замена создаёт новый media ID и применяется к слоту после сохранения.

## Состояния редактора и промпта

| Состояние / событие | Результат |
|---|---|
| Нет модели | Последующие поля скрыты |
| Выбрана модель | Показаны возможности и доступные персонажи |
| Выбраны персонажи | Показан выбор кадров соответствующего вида |
| Выбраны кадры | Распределение фото, параметры выходного видео, фиксация |
| Недопустимая фиксация | Ошибка; нижние поля не раскрываются |
| Фиксация | Верхние поля отключены; материалы и тесты доступны; новый шаблон |
| Ручная правка промпта | Текст становится авторским, сохраняется при добавлении references |
| References меняются при шаблонном тексте | Загрузить готовый файл для нового количества references |
| References меняются при авторском тексте | Сохранить текст; напомнить проверить ссылки |
| Разблокировка | Сброс нижних полей; сохранение привязанного V2V-исходника, карточки слота и кеша тестовых фото |
| Смена верхней настройки | Пересчёт; недопустимые следующие значения очищены; ручной текст сброшен |
| Тесты включены | Строго C×K или K фото, без автодублирования |
| Сохранение / открытие | Сохранённый валидный setup открывается зафиксированным; незавершённый нижний ввод не делает слот готовым к запуску |

Показ панели «Тесты» не запускает работу. Режим генерации сохраняется отдельно
от кнопки запуска: real, проверка входов или полный проход с тестовым видео
([PRD](../../.memory-bank/prd.md#постоянные-инструменты-тестирования-слота)).
При включённой симуляции заголовок редактора показывает «Тестирование!» и пояснение
«отключите тесты чтобы слот заработал»; панель тестов раскрыта и не сворачивается,
включая повторное открытие и перезагрузку. Реальную генерацию возвращают выбором fal.ai и сохранением.
Старый `simulateGeneration=true` без `simulationOutput` сохраняет проверку входов.
Кеш не смешивает персональные и групповые позиции; неиспользуемые фото не отправляются.
Обложка, картинки ракурсов, P2V-демо и последний результат не включаются в payload.
История уже запущенных тестов/последнее готовое видео не удаляется при разблокировке.

## Состояния съёмки и пересъёмки

| Состояние / событие | Поведение |
|---|---|
| Начало | План из snapshot; индексы кадров уникальны, известны человек и ракурс |
| 1/2 человека | K поз каждого по порядку; перед вторым — ожидание готовности оператора |
| 3+ | K групповых кадров; перед каждым показан образец №5 |
| Countdown | Образец и инструкция видны весь заданный отсчёт (по умолчанию 5 секунд) |
| Pause | Переход в ручной режим. Тап по Live View запускает один отсчёт и кадр. При переключении отсчёт останавливается. Если затвор уже отправлен, получить текущий JPEG и остановить дальнейшую автоматику |
| Play | Включить автоматическую серию. Первый и последующие отсчёты имеют заданную длительность |
| Начать заново | После подтверждения очистить локальную серию и начать с первой позы в текущем режиме; отмена сохраняет серию |
| Перефоткать последнее | Сразу убрать последний успешно снятый кадр и миниатюру, вернуться на его позицию для пересъёмки; остальные сохранить |
| Нет снятых кадров | «Перефоткать последнее» отключено |
| Камера уже снимает / ожидается JPEG | Не посылать второй спуск; кнопки пересъёмки недоступны до окончания операции |
| Карточка сюжета | Подтверждение смены возвращает каталог и сбрасывает локальную серию; отмена сохраняет её; при pending JPEG и после Finish смена недоступна |
| Ошибка кадра | Сохранить успешные; после отправленного затвора повторять ожидание/скачивание того же JPEG без нового спуска |
| Последний кадр готов | Дать проверить серию и автоматически начать передачу через заданный интервал (по умолчанию 3 секунды). «Завершить фотосессию» запускает её сразу |
| Завершить фотосессию | Зафиксировать выбранные байты, отключить пересъёмки; загрузить и finalize общим путём |
| Ошибка передачи | Повтор передачи согласованных кадров; без нового спуска и без новой генерации |

В «Параметрах» администратор задаёт пять образцов: №1 главный; №2 улыбаемся,
наклонившись к камере одним плечом; №3 профиль; №4 смотрим вниз на обувь оператора;
№5 групповое фото. У каждого образца есть необязательная подпись до 120 символов.
При старте сессии текст фиксируется вместе с изображением и показывается под образцом текущего ракурса. При K<4 берутся первые K индивидуальных ракурсов. Образцы не
передаются в AI. Отсутствующий загруженный образец явно обозначен; инструкция остаётся.

## Принятые трактовки API и границы доказательства

Решение оператора: применять лимиты по документации API без дополнительных
ограничений для перестраховки. Неоднозначности не блокируют внедрение; если реальные
запросы выявят расхождения, уточнить правило и источник при отладке. Это не отменяет
ранее согласованные продуктовые варианты людей/кадров и выходного видео.

- **O3 P2V: E + ordinary ≤7 без видео.** Источники:
  [официальный Kling Omni guide](https://kling.ai/quickstart/klingai-video-3-omni-model-user-guide),
  [fal endpoint](https://fal.ai/models/fal-ai/kling-video/o3/pro/reference-to-video/api).
  Неоднозначность: fal schema не задаёт точного максимума, а prose упоминает четыре
  только «when using video». Выбранная трактовка: для нашего image-only входа
  применяется семь по Kling guide; искусственное ограничение четырьмя не вводится.
- **Kling 4: до 10 ordinary images сверх индивидуальных Elements.** Источники:
  [fal Kling 4](https://fal.ai/kling-4),
  [официальный Kling 4 guide](https://kling.ai/quickstart/kling-4-model-user-guide),
  [схемы четырёх endpoint](../../.memory-bank/analysis/slot-setup-api/kling-v4.md).
  Выбранная трактовка: E≤7, ordinary≤10, E + ordinary + V≤15; V=1 для V2V, иначе 0.
  Вложенные ракурсы считаются частью Element, не отдельными assets. Неоднозначность:
  точный учёт вложенных фото и применимость общего потолка к Flash не полностью
  раскрыты в fal. Дополнительный предел в 15 физических фото/видео не вводится.
