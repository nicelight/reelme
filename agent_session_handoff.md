# ReelMe — продолжение настройки слотов

## Основная цель — не матрица

**Переработать интерфейс слотов и фотосессии и довести согласованный сценарий до
работающего состояния.** Администратор последовательно задаёт setup, видит лимиты,
фиксирует выбор, получает правильные поля материалов/промпта/тестов; оператор
управляет съёмкой с нужными ракурсами и пересъёмками. Backend обеспечивает те же
правила, правильные входы модели и совместимость начатых сессий.

Матрица, готовые промпты и lookup — только подготовительные артефакты.
**Основная задача не завершена.** Оператор отдельно подчеркнул порядок дальнейшей
работы: **план внедрения → индексированные задачи → реализация → проверки**.
Не подменять переработку интерфейса подготовкой документации или файлов каталога.

**Ограничение проверки от оператора:** НЕ проводить тесты всех 800+ вариантов
промптов. Для задач и приёмки достаточно выборки разных API-ветвей, людей/группы,
граничных references и пустого Recast. Не добавлять полный перебор в unit/API/UI
или реальные генерации. Подготовленный тест уже сокращён до выборки; старые
сведения о полной проверке ниже — история подготовки, не требование повторять её.

## Точка остановки

Оператор попросил **сформировать машинную матрицу и связанные готовые `.md`-промпты,
записать этот handoff и остановиться перед сжатием контекста**. Этот промежуточный
этап выполнен. После возобновления сначала уточнить существующий план внедрения
до исполнимых результатов и сформировать задачи; затем выполнять их.

Работать по `AGENTS.md`, отвечать по-русски, придерживаться KISS. Повторное
согласование принятых ниже решений не требуется. Коммит, push и deploy не выполнялись.
Рабочее дерево содержит все изменения этой сессии; они не закоммичены.

## Готовые машинные артефакты

- [src/shared/slot-setup-matrix.json](src/shared/slot-setup-matrix.json): 11 endpoint,
  108 сочетаний «модель + люди/группа + число кадров», ссылки на 813 файлов.
- [src/shared/slot-prompt-selection.ts](src/shared/slot-prompt-selection.ts):
  `selectSlotPrompt()` проверяет точное сочетание и возвращает `{file, url}`.
  Он не собирает текст, не делает fetch, не изменяет слот и не валидирует весь
  набор параметров выходного видео. Неверный вариант вызывает ошибку, без fallback.
- [public/slot-prompts/](public/slot-prompts/): **813 окончательных `.md`**, по
  одному на комбинацию с фактическим количеством дополнительных референсов.
  Одинаковые копии прямо разрешены оператором. Два Recast-файла — нулевой длины.
- [scripts/generate-slot-prompts.mjs](scripts/generate-slot-prompts.mjs): офлайн-
  материализация JSON и файлов. Не импортировать и не запускать её в приложении.
  Генератор не использует LLM и не читает описание слота.
- [tests/slot-prompt-selection.test.ts](tests/slot-prompt-selection.test.ts):
  выборочная проверка бюджетов, ссылок, токенов, выходных опций и ошибок выбора;
  без чтения всех 813 файлов.

Схема выбора: модель по `id` и `mode`; `captureVariants` по `participants`
(`1`, `2`, `'group'`) и `photosPerParticipant`; затем
`promptFiles[additionalReferenceCount]`. Этот индекс — **фактическое число
добавленных фото**, не свободный остаток и не фото камеры. `group` — UI-значение «3+».
Пути относительны `public/slot-prompts`, URL base — `/slot-prompts/`.

Пример: H3 Reference, 2 человека × 4 кадра, 1 дополнительное фото →
[готовый промпт](public/slot-prompts/h3-reference/people-2__photos-4__refs-1.md).
Внутри уже перечислены Image 1–4 для первого, 5–8 для второго и Image 9 для сцены;
код ничего не подставляет. Gemini использует literal `<IMAGE_REF_0>` с нуля,
Vidu — `[@reference_image_1]`, Kling — `@Element1` и `@Image1`. У O1 исходный ролик
назван `source video`, у O3/V4 V2V — `@Video1`.

Качество, ориентация и длительность не меняют промпт и не умножают число файлов.
JSON содержит допустимые качество/ratio, но не заменяет весь текущий каталог
моделей: например, длительности и ограничения файлов нужно согласованно сохранить
в существующем модельном контракте при внедрении.

Старые 11 Markdown-инструкций из `docs/slot-setup/prompts/` **удалены**; их ссылки
заменены примерами готовых текстов. Не восстанавливать runtime-шаблонизатор вместо
готовых файлов: именно это оператор исправил в предыдущем результате.

## Принятые решения оператора

- Последовательность: режим/модель → персонажи → кадры → параметры видео →
  «Зафиксировать выбор» → references/промпт/тесты. Фиксация блокирует верхние поля.
  Разблокировка сбрасывает нижние настройки и ручной промпт, оставляя тестовые фото.
- Люди `1`, `2`, `3+`. Два человека снимаются последовательными равными наборами,
  перед вторым ожидается готовность. Группа — один набор групповых фото, без Elements.
- Kling индивидуально **2–4 разных фото на Element**; 1 отключён. Группа — 1–4
  обычных изображения. Остальные P2V — 1–4 кадра на человека/группу.
- Recast — один кадр на человека, доступны 1/2 человека, группа отключена;
  дополнительные фото сцены не передаются. Промпт пустой по умолчанию, но редактируемый
  и необязательный. Подпись: **РЕКОМЕНДУЕТСЯ ОСТАВИТЬ ПРОМПТ ПУСТЫМ!**.
- При неравных наборах двух людей фиксация запрещена с точным текстом:
  «выберите меньшее количество фотографий во время фотосессии.»
- Шаблонные промпты общие, без описания слота и текстового AI inference.
  Смена верхнего setup сбрасывает ручной текст. Изменение/удаление/замена references
  **сохраняет ручной текст**, но показывает напоминание проверить ссылки.
  Это действует и при неизменном количестве references. Пока текст не правили,
  можно загрузить файл для нового количества; не затирать ручную правку поздним fetch.
- Каждый тестовый кадр требует своего JPEG. Никаких автоматических копий одного
  файла на все позиции. Кеш должен переживать смену setup, но сложное восстановление
  после закрытия браузера не нужно. Не хранить байты JPEG/base64 в localStorage.
  Групповые и индивидуальные назначения не смешивать; лишний кеш не отправлять.
- «Тесты» раскрывает панель; существующий `simulateGeneration` остаётся отдельной
  явной настройкой. Готовое прошлое видео/запущенный тест не удаляются сбросом формы.
- Съёмка: Pause/Continue, **Restart фотосессия**, **Перефоткать последнее**.
  Continue начинает полные 3–2–1; restart возвращает к первому кадру и ждёт запуска;
  пересъёмка заменяет последнюю завершённую позицию, сохраняя остальные.
  Во время спуска/ожидания JPEG второй спуск и пересъёмки запрещены.
- После последнего кадра показывается результат; передача начинается только по
  **Завершить фотосессию**. До этой кнопки доступны пересъёмки, после — только
  передача/повтор передачи. Не смешивать restart съёмки с retry загрузки.
- Пять загружаемых из отдельной админской страницы образцов: главный; улыбка
  с наклоном к камере одним плечом; профиль; взгляд вниз на обувь оператора;
  групповое фото. Группа всегда видит пятый образец. Образец виден во время отсчёта.
- Качество только 720p (768P для MiniMax) / 1080p, реально поддержанное endpoint.
  Flash только 720p; O1/O3 не имеют `resolution`. Не имитировать выбор.
  Горизонталь/вертикаль и совместимые ratio; без crop/upscale/поворота. Для V2V
  без `aspect_ratio` направление определяется исходником. Квадрат/auto/adaptive
  не включены в двухориентационный UI.
- Ролик закреплён за слотом. По текущему указанию оператора создана только
  [папка и инструкция](media/template-videos/readme_media.md), без самих роликов.
  Имена `<slot-id>__landscape.mp4` / `<slot-id>__portrait.mp4`; форматы описаны там.
  Отсутствующий ролик не заменять случайным примером. Плеер должен показывать
  тот же исходник, который используется при генерации.

## Лимиты API — решения закрыты, не спрашивать повторно

Оператор выбрал **документацию API без дополнительных ограничений для перестраховки**.
Неоднозначности и источники остаются в матрице; расхождения реальных вызовов
разбираются при отладке, а не блокируют внедрение.

- O1/O3 V2V: Elements + ordinary images ≤4; ракурсы внутри Element отдельно
  не вычитаются. При двух людях по 4 кадра остаются 2 дополнительных фото.
- O3 P2V: image-only предел **7** по официальному Kling guide. Fal schema не
  задаёт точного max; условие 4 в prose относится к видео. Не вводить предел 4.
- Kling 4: до 10 ordinary images сверх индивидуальных Elements, до 7 Elements,
  общий бюджет `E + I + V ≤15`, где V=1 для V2V. Element считается одной единицей;
  не вводить дополнительный потолок 15 физических файлов. Точный учёт вложенных
  ракурсов/применимость общего потолка к Flash не полностью раскрыты — это отмечено.
- H3 Reference: **9 фото**, не 12 (12 — смешанный медиабюджет). Vidu — 12, Gemini — 10.
- Elements не означают детекцию лиц нашим приложением. Лимит файлов не равен
  документированной гарантии количества узнаваемых людей. Группа не раскладывается
  автоматически на людей, лица или Elements.

## Что ещё НЕ внедрено и где возможны ошибки продолжения

- **UI и pipeline остаются прежними.** Не включать их в отчёт как готовые:
  `scenarios.ts` всё ещё требует один/четыре кадра косвенно, запрещает Recast prompt,
  ограничивает references тремя и не разрешает их в V2V. DTO людей/кадров пока нет.
- `src/shared/capture.ts`: `expectedPhotos: 1 | 4`, прежние позы.
  `scenarios/store.ts`: snapshot вычисляет число только из модели.
  `sessions/index.ts`: regex позиции `0..3`, `photoPoses.slice`, один fixture
  копируется на все тестовые позиции. `model-input.ts`: один Element и фиксированные
  1/4 фото. `generation.ts` и проверки полноты должны согласованно перейти на новый план.
- Новая JSON-матрица должна стать общей основой допустимых setup и выбора файла;
  не копировать формулы в независимые UI/server реализации. При этом человеческая
  матрица остаётся объяснением поведения, а не runtime-парсером Markdown.
- **Статическая выдача ещё отсутствует:** Vite уже кладёт готовые файлы в
  `dist/client/slot-prompts`, но `src/server/app.ts` раздаёт лишь `/assets/`.
  При подключении редактора добавить `/slot-prompts/` с ревалидацией/без длительного
  immutable-cache для стабильных имён. Сейчас URL из lookup сам по себе не означает HTTP 200.
- Загружать через `response.text()`, без Markdown-rendering и без подстановок;
  проверять HTTP-ошибку отдельно от пустого Recast-файла. Исключить гонку старого
  ответа с новым setup/ручной правкой. Верхняя смена сбрасывает текст даже если
  resolution/orientation ведут к тому же самому файлу.
- Новые snapshots должны хранить конкретный план и ссылки на образцы/материалы;
  правка слота, ролика, админских поз не меняет начатую сессию. Старые snapshots
  без нового плана продолжают старый смысл 1/4 и старые позы, без массового переписывания.
  Старый один testPhotoId не доказывает полный новый многокадровый набор;
  незавершённые старые тесты требуют совместимого пути продолжения.
- После нажатия «Завершить фотосессию» работаем с принятым набором Blobs;
  retry передачи не снимает снова. Восстановление частично загруженной серии не
  должно терять принятые сервером позиции или незаметно финализировать старые кадры
  после новой пересъёмки. Нормальные restart/retake выполняются до начала передачи.
- Добавить учёт test-photo массивов и образцов поз в очистку материалов;
  текущий `materialIds()` знает только прежние поля. Замены файлов — новые media IDs,
  не перезапись старого пути, используемого сессией.
- Для привязки исходника новому слоту нужен стабильный ID до подготовки файла;
  этот стык перечислен в плане, но ещё не реализован. Сами фильмы сейчас отсутствуют.
- Во всех новых/существенно изменённых модулях, использующих матрицу, заголовок
  Module contract должен ссылаться на `docs/slot-setup/matrix.md`.

- `npm run check:slot-prompts` — PASS, 11 моделей / 108 строк / 813 `.md`, два пустых.
- `node --import tsx --test tests/slot-prompt-selection.test.ts` — PASS, **4/4**:
  полное покрытие, правильные бюджеты/индексы, уникальность путей, соответствие
  токенов реальным входам, группы/индивиды, неправильные сочетания, выходные опции.
- `npm run check` — PASS, Svelte 0 errors / 0 warnings, TypeScript без ошибок.
- `npm run build` — PASS. Отдельно сравнены байты всех 813 исходных и скопированных
  Vite файлов; `dist/shared/slot-setup-matrix.json` также создан tsc.
- Всего тексты занимают 436192 байта, самый длинный — 947 символов; пределы API соблюдены.
- `git diff --check` — PASS. Финально проверены 8 документов и 65 локальных ссылок,

Команды генератора: `npm run generate:slot-prompts` перезаписывает каталог/файлы;
`npm run check:slot-prompts` ничего не меняет. После изменения массового набора

будут перезаписаны. Сохранённый ручной промпт слота не изменяет эти общие файлы.
Полный `check:slot-prompts` не включать в обычные задачи/CI и не запускать по
умолчанию; это отдельная утилита диагностики, а не требование приёмки.

## Состояние проекта и ближайшая работа

PRD, REQ, FT-001/002/003/006 и индексы связаны с новым объёмом; старые завершённые
задачи и их доказательства сохранены. В реализованных HTTP/domain/lifecycle
контрактах есть явная ссылка на целевое обновление: текущий wire-format не выдаётся
за уже изменённый. Новые индексированные задачи внедрения ещё не созданы;
прочитать `.memory-bank/tasks/index.json` перед назначением следующих ID.

Практическое продолжение:

1. Проверить и довести существующий план до достаточного покрытия именно нового
   интерфейса и связанного сценария: последовательность/сбросы, загрузка готового
   промпта, материалы и параметры видео, тестовые наборы, админские ракурсы,
   pause/restart/retake/finish, серверная согласованность и совместимость.
2. По плану сформировать обычные JSON-задачи в `.memory-bank/tasks/` с регистрацией
   в индексе, зависимостями, связанными требованиями и критериями результата.
   Использовать актуальные task schema и skill `feature-to-tasks`; не считать
   четыре раздела текущего плана уже созданными задачами.
3. Выполнить задачи и проверки. Подготовленный каталог повторно не создавать;
   подключить его к редактору и закончить весь согласованный пользовательский путь.

Не переделывать промпты обратно в инструкции и не проводить заново уже принятое
обсуждение лимитов. Завершение — работающий интерфейс и проверенный сквозной
сценарий, а не наличие матрицы, промптов или плана.

не выполнял. Не восстанавливать и не включать его в свои изменения автоматически.
