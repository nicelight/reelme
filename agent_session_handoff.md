## Выполненное внедрение

- [TASK-016](.memory-bank/tasks/TASK-016-T2-FT-001-W13.task.json): общий setup,
  конкретный snapshot-план до восьми кадров, приём, model payload и legacy.
- [TASK-017](.memory-bank/tasks/TASK-017-T2-FT-001-W14.task.json): последовательный
  редактор, фиксация/сбросы, готовые промпты, отдельные тестовые JPEG и их кеш.
  Завершена, включая независимый UI smoke на широком экране и при ширине 375 px.

`src/shared/slot-setup.ts` содержит `getSlotSetup`, `buildPosePlan`,
`defaultSlotSetup`, `allocatePhotoBudget`, `captureGuides`, `unequalPhotoMessage`.
Новый setup: `participants: 1|2|'group'`, `photosPerParticipant`, `orientation`,
поддерживаемый `aspectRatio`. Допустимые варианты/выходные параметры берутся из JSON.
Отдельные capability metadata добавлены для честного текста API-лимитов; варианты
съёмки и все промпт-файлы остались прежними.

`SlotSnapshot.posePlan` хранит конкретные позиции с участником/образцом;
`expectedPhotos` равен длине плана. `snapshotPosePlan` читает сохранённый план,
а при его отсутствии — прежние 1/4 и старые позы. Raw legacy-слоты до первого
нового сохранения запускаются прежним путём. `editorSlot` даёт нормализованную
проекцию без автоматической записи. Старые разрешения остаются видимыми,
но новое сохранение требует допустимый setup.

SQLite `capture_photos` теперь допускает 0..7. Миграция сохраняет фото,
FK/provider tokens/URLs, snapshots и подтверждённые request_id. Приём дополнительно
проверяет позицию по конкретному плану. Для Kling люди дают отдельные Elements,
группа — ordinary images; Recast prompt редактируемый и необязательный.
Новый V2V draft без видео сохраняется, но не появляется в каталоге и не запускается.

`SlotEditor.svelte` отделён от App; верхние совместимые значения сохраняются
при смене модели. Unlock очищает нижние настройки, сохраняет V2V-исходник,
карточку и кеш JPEG. Ручной prompt сохраняется при любой смене references
с напоминанием; поздний fetch не перезаписывает ручной текст/новый setup.
Статическая выдача `/slot-prompts/` работает с `no-cache`; пустой Recast — валидный файл.

`testPhotoIds` — активный полный набор в порядке плана. UI-кеш использует
человек/ракурс и отдельно group/номер кадра; лишние фото не отправляются.
Каждая позиция нового теста получает собственный JPEG, без автокопий одного файла.
Legacy `testPhotoId` сохраняется для старых тестов/retry. Источники теста закреплены
в snapshot, учитываются в cleanup и не попадают в generation. SlotTest сохраняет
запущенный тест и последний ready-ролик при сбросах формы.

README и HTTP/domain/lifecycle/integration контракты обновлены вместе с внедрением.
Ссылки `docs/slot-setup/matrix.md` проверены в начальных комментариях всех новых
и изменённых связанных исходников, включая косвенных потребителей.

затвора/restart/retake. Использовать read-only признак pending; повтор получения
того же JPEG не посылает новый shutter.

Дополнение оператора KISS: **без IndexedDB-кеша JPEG**. Повтор передачи работает
из RAM. После reload при потере недостающих Blobs — явная остановка этой сессии,
с сохранением уже принятых позиций, без скрытой пересъёмки/неполного finalize.
Допустим небольшой sessionStorage-маркер начала передачи, без байтов фото.
