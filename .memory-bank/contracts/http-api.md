# HTTP API ReelMe

Контракты API по [PRD](../prd.md); реализованный объём и проверки — в [задачах](../tasks/index.json).
Префикс — /api, кроме страницы QR и скачивания. [Права](access.md) проверяет сервер.
Ошибки содержат code/message без секретов и внутренних ответов провайдера.

## Каталог и слоты

| Операция | Доступ | Данные |
|---|---|---|
| GET /catalog?page=1, /catalog/:id | Установка | Видимые сюжеты, по 12 на страницу; описание, миниатюра, пример видео |
| GET /catalog/:id/media/:mediaId | Установка | Только миниатюра или пример видео текущего видимого сюжета; байты с Range |
| GET /admin/slots, /admin/slots/:id | Администратор | Список и полная конфигурация слота |
| POST /admin/slot-media | Администратор | Multipart `file` → метаданные с `id` материала |
| GET /admin/slot-media/:id, /admin/slot-media/:id/info | Администратор | Байты (с Range) / метаданные материала |
| POST /admin/slots, PUT /admin/slots/:id | Администратор | Сохранение конфигурации |

Каталог возвращает `CatalogPage` (`items`, `page`, `pageSize=12`, `total`, `totalPages`),
карточка — `CatalogItem` из [capture.ts](../../src/shared/capture.ts). `previewId`
ссылается на исходник V2V или демо P2V; без демо отсутствует. Скрытый/несуществующий
сюжет и материал вне его текущей публичной карточки возвращают 404. Промпты,
настройки моделей и P2V-референсы не входят в проекцию каталога.

Конфигурация: описание, видимость, миниатюра, режим, модель, параметры и материалы PRD.
Сервер проверяет допустимые входы по [схемам моделей](../analysis/fal-api.md).
Recast не получает промпт, демо P2V не входит в генерацию. При старте сессия сохраняет
текущие настройки и конкретные материалы. Отдельного контроля конкурентных редакций нет.
Медиа каталога доступны с ключом установки, медиа редактора — с аккаунтом администратора.

Форма JSON редактора — `SlotInput` в [scenarios.ts](../../src/shared/scenarios.ts).
Сохраняются только поля выбранного режима/модели; неизвестные поля отвергаются.
Для Recast `recastShotsConfirmed` фиксирует подтверждение администратора о кадрах
≤15 с: ffprobe проверяет общую длительность, но не смысловые границы кадров.
H3 Reference использует `promptExpansionMode: disabled`. Ограничения загрузки
и проверка файлов — в [README](../../README.md#работа-с-редактором).

## Съёмка

Все операции требуют ключ установки.

| Операция | Данные и результат |
|---|---|
| POST /capture/sessions | startRequestId, slotId → sessionId, дата, номер, план поз |
| GET /capture/sessions/:id | `CaptureStatus`: состояние, принятые позиции, полный набор и подтверждение finalize |
| PUT /capture/sessions/:id/photos/:poseIndex | Multipart `file` (JPEG) → `CaptureStatus` с принятой позицией |
| POST /capture/sessions/:id/finalize | Полный набор → `submit_pending`, `CaptureStatus.finalized=true` |

Первый старт возвращает 201, повтор — 200 с тем же `StartReceipt` из
[capture.ts](../../src/shared/capture.ts). `startRequestId` и `slotId` — UUID.
Повтор одного ключа для другого слота даёт 409; для того же слота возвращается
сохранённая сессия, даже после скрытия слота или смены суток. Проверка текущей
видимости выполняется перед первым стартом. Номер в ответе API ещё не показывается
посетителю; клиент хранит результат и план поз для съёмки/передачи.
Дата, номер и план сохраняются; `state` в повторном ответе отражает актуальное состояние.

`CaptureStatus` из [capture.ts](../../src/shared/capture.ts) содержит sessionId,
дату, номер, исходный план и state, а также `acceptedPoseIndices` (индексы с нуля),
`complete` (полный набор на сервере) и `finalized` (набор передан на обработку).
Полный, но ещё не финализированный набор не разрешает показ номера. GET/PUT/finalize
возвращают 200; неполный finalize и запись после finalize — 409. Неверный JPEG
или индекс — 400, неизвестная сессия — 404, превышение 20 MiB — 413.
Принимается один JPEG в multipart-поле `file`, до 40 мегапикселей; проверяется
декодирование, оригинальные байты сохраняются без преобразования.

Повтор старта возвращает существующую сессию по ключу запроса. После удаления отдельный
реестр старых ключей не сохраняется. Загрузка адресует конкретную позицию; до finalize
повтор записывает тот же кадр в неё, не затрагивая остальные. После finalize фото закрыты
для изменений. Сервер проверяет JPEG и количество фото, но не ведёт протокол сравнения hash.
Повтор finalize возвращает текущее состояние без нового перехода в обработку.
После подтверждения finalize установка показывает номер и освобождается.
`submit_pending` в SQLite — граница FT-003; потребитель генерации реализуется отдельно. Ошибка камеры/загрузки допускает ручной повтор.

## Экран и архив

| Операция | Доступ | Результат |
|---|---|---|
| GET /display/today | Оператор | Сегодняшние номера, этапы, ошибки и карточки |
| GET /events, /events/:date | Оператор/администратор | Прошедшие мероприятия, размеры и галерея |
| DELETE /events/:date | Администратор | Удаление прошедшего мероприятия после подтверждения в UI |

Карточка содержит исходное фото, кадр результата, номер и QR. Медиа проверяют права
соответствующего экрана; просмотр карточки не считается открытием формы посетителя.
API не возвращает полные email, ключи и URLs fal. Отбор по времени и шесть этапов —
[жизненный цикл](../states/lifecycle-map.md#шесть-этапов-на-общем-экране).
Сегодняшний день не входит в архив и недоступен для удаления.

## Получение и email

Страница QR — /receive/:token. Токен даёт доступ только к своей сессии.

| Операция | Результат |
|---|---|
| GET /receive/:token | Фото, номер, состояние письма и доступность отправки |
| POST /receive/:token/opened | Фиксация открытия формы |
| POST /receive/:token/email | email → постановка письма на отправку |
| GET /download/:token (вне /api) | Видео по ссылке из письма |

Сервер проверяет email и состояние: во время отправки второе письмо не запускается,
после успеха повтор запрещён, после ошибки возможен ручной повтор с исправлением адреса.
Потерянное подтверждение SMTP.BZ не вызывает автоматическую повторную отправку.
Первое подтверждение email запускает трёхминутный срок, повтор его не меняет.
Состояние письма читается из той же формы; отдельного API истории попыток нет.
Удаление мероприятия закрывает выдачу по ссылкам. Медиа не доступны открытым каталогом.

## Граница генерации и выдачи

FT-003 создаёт provider-media URLs по [контракту файлов](integrations.md#файлы-и-срок-хранения),
подготовленное видео/кадр и затем собственную download-ссылку и receive-форму.
До готовности формы/ссылки сессия остаётся `preparing`; `ready` не означает отправку письма.
TASK-008 реализует страницу формы, GET её данных и POST opened/email с сохранением
`pending` и времени первого подтверждения по существующим правилам выше. Это позволяет
проверить доступную рабочую форму без зависимости генерации от SMTP.
FT-004 переиспользует эти маршруты/данные: добавляет SMTP-обработчик, QR/общий экран,
публичные этапы и скрытие. Пока почтовый обработчик не подключён, форма показывает
ожидание отправки, а не `sent`; фактическая доставка принимается в FT-004.
Данные готовой карточки (фото, кадр, номер, URL формы) готовит FT-003, публикует FT-004.
GET capture-state возвращает безопасный код/текст ошибки своей сессии; общий экран
ошибок реализуется в FT-004. Ответы клиентам не включают provider URLs и секреты.
