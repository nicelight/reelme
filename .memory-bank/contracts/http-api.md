# HTTP API ReelMe

Проект API по [PRD](../prd.md); реализация ещё отсутствует.
Префикс — /api, кроме страницы QR и скачивания. [Права](access.md) проверяет сервер.
Ошибки содержат code/message без секретов и внутренних ответов провайдера.

## Каталог и слоты

| Операция | Доступ | Данные |
|---|---|---|
| GET /catalog, /catalog/:id | Установка | Видимые сюжеты, по 12 на страницу; описание, миниатюра, пример видео |
| GET /admin/slots, /admin/slots/:id | Администратор | Список и полная конфигурация слота |
| POST /admin/slot-media | Администратор | Загрузка материала → mediaId |
| POST /admin/slots, PUT /admin/slots/:id | Администратор | Сохранение конфигурации |

Конфигурация: описание, видимость, миниатюра, режим, модель, параметры и материалы PRD.
Сервер проверяет допустимые входы по [схемам моделей](../analysis/fal-api.md).
Recast не получает промпт, демо P2V не входит в генерацию. При старте сессия сохраняет
текущие настройки и конкретные материалы. Отдельного контроля конкурентных редакций нет.
Медиа каталога доступны с ключом установки, медиа редактора — с аккаунтом администратора.

## Съёмка

Все операции требуют ключ установки.

| Операция | Данные и результат |
|---|---|
| POST /capture/sessions | startRequestId, slotId → sessionId, дата, номер, план поз |
| GET /capture/sessions/:id | Состояние, принятые позиции, подтверждение полного набора |
| PUT /capture/sessions/:id/photos/:poseIndex | JPEG текущего шага → подтверждение сохранения |
| POST /capture/sessions/:id/finalize | Полный набор → начало фоновой обработки |

Повтор старта возвращает существующую сессию по ключу запроса. После удаления отдельный
реестр старых ключей не сохраняется. Загрузка адресует конкретную позицию; до finalize
повтор записывает тот же кадр в неё, не затрагивая остальные. После finalize фото закрыты
для изменений. Сервер проверяет JPEG и количество фото, но не ведёт протокол сравнения hash.
Повтор finalize не запускает новую генерацию. После подтверждения полного набора
установка показывает номер и освобождается. Ошибка камеры/загрузки допускает ручной повтор.

## Экран и архив

| Операция | Доступ | Результат |
|---|---|---|
| GET /display/today | Оператор | Сегодняшние номера, этапы, ошибки и карточки |
| GET /events, /events/:date | Оператор/администратор | Прошедшие мероприятия, размеры и галерея |
| DELETE /events/:date | Администратор | Удаление прошедшего мероприятия после подтверждения в UI |

Карточка содержит исходное фото, кадр результата, номер и QR. Медиа проверяют права
соответствующего экрана; просмотр карточки не считается открытием формы посетителя.
API не возвращает полные email, ключи и URLs fal. Отбор по времени и шесть этапов —
[жизненный цикл](../states/lifecycle-map.md#шесть-этапов-на-общем-экране).
Сегодняшний день не входит в архив и недоступен для удаления.

## Получение и email

Страница QR — /receive/:token. Токен даёт доступ только к своей сессии.

| Операция | Результат |
|---|---|
| GET /receive/:token | Фото, номер, состояние письма и доступность отправки |
| POST /receive/:token/opened | Фиксация открытия формы |
| POST /receive/:token/email | email → постановка письма на отправку |
| GET /download/:token (вне /api) | Видео по ссылке из письма |

Сервер проверяет email и состояние: во время отправки второе письмо не запускается,
после успеха повтор запрещён, после ошибки возможен ручной повтор с исправлением адреса.
Потерянное подтверждение SMTP.BZ не вызывает автоматическую повторную отправку.
Первое подтверждение email запускает трёхминутный срок, повтор его не меняет.
Состояние письма читается из той же формы; отдельного API истории попыток нет.
Удаление мероприятия закрывает выдачу по ссылкам. Медиа не доступны открытым каталогом.
