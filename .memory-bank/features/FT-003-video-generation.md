# FT-003 — Генерация и подготовка видео

Сервер превращает фотографии и выбранный сюжет в доступный видеофайл, сохраняя связь
с фотосессией. Поведение — [PRD](../prd.md#фоновая-генерация), интеграция — [fal API](../analysis/fal-api.md).

## Acceptance Criteria

### FT-003-AC-001
- REQ: REQ-007
- Результат: доступны все пять V2V и шесть P2V endpoint из исследования API.
  Recast получает одно фото и не получает промпт. Остальные получают четыре фото человека;
  для P2V дополнительные фото слота сохраняют свою роль и логический порядок после фото человека.
  Поля, промпты и разрешения соответствуют API выбранной модели.
- Проверка: контрактная матрица всех адаптеров по официальным схемам и локальный
  технический проход с управляемым fal-транспортом и реальной проверкой файлов.
  Обязательные реальные API-прогоны всех fal-моделей на этапе разработки отменены
  оператором; совместимость с живым API остаётся непроверенной.
  Художественная оценка не входит в проверку.

### FT-003-AC-002
- REQ: REQ-007
- Результат: неизменные видео/референсы слота используются по сохранённым URL;
  новая фотосессия не загружает их байты повторно. Демовидео P2V не отправляется модели.
- Проверка: две сессии с одним слотом; наблюдение входных URL и операций загрузки.

### FT-003-AC-003
- REQ: REQ-008
- Результат: отсутствие подтверждения допускает повтор submit; полученный `request_id`
  сохраняется и наблюдается без новых запусков. Встроенные retries fal включены.
  Дубль при потерянном подтверждении допустим, отдельная дедупликация не требуется.
- Проверка: смоделированная потеря submit-ответа, подтверждённый ID, временный сбой опроса
  и окончательная ошибка модели; последние два случая не инициируют новую генерацию.

### FT-003-AC-004
- REQ: REQ-009
- Результат: успех означает воспроизводимый файл, собственную ссылку и доступную форму.
  При сбое скачивания повторяется получение того же результата. Терминальная ошибка fal
  записана и видна у сессии. Завершение обработчика не удаляет сессию и не ждёт отправки email.
- Проверка: успех и повреждённый/пустой результат, сбой скачивания, `COMPLETED` с ошибкой;
  проверка выдаваемого файла и финального состояния.

## Реализация и проверка

Модельные поля заданы [справкой fal](../analysis/fal-api.md), очередь и файлы —
[интеграциями](../contracts/integrations.md#генерация-fal). Обязательные реальные API-прогоны на этапе разработки отменены оператором.

Задачи — в [индексе](../tasks/index.json):

- [TASK-006](../tasks/TASK-006-T3-FT-003-W4.task.json): Recast, выдача входов fal,
  обработка/восстановление и проверенное локальное видео (Recast из AC-001,
  V2V-часть AC-002, AC-003, файловая часть AC-004). Требует TASK-004.
- [TASK-007](../tasks/TASK-007-T2-FT-003-W5.task.json): остальные десять моделей
  и P2V-материалы (оставшаяся часть AC-001/002); требует TASK-006.
- [TASK-008](../tasks/TASK-008-T3-FT-003-W5.task.json): собственная ссылка,
  форма получения и переход ready (оставшаяся часть AC-004); требует TASK-006.

TASK-006/007 закрываются по локальным проверкам. Реальные вызовы fal не обязательны
на этапе разработки по решению оператора; тестовые ответы не доказывают живой API.
Граница формы и отправки письма описана в [HTTP-контракте](../contracts/http-api.md#граница-генерации-и-выдачи).
