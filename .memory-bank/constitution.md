# Project Constitution

## Project principles

- KISS: простейшее достаточное решение, без overengineering и механизмов «на вырост».
- Проработка требований, архитектуры и спецификаций — приоритет до реализации.
  Обосновывать границы компонентов, контракты, состояния и поведение при сбоях;
  переходить к продуктовому коду после согласования существенных решений.
- До решения или исправления сравнить пользу с затратами на реализацию и поддержку,
  сложностью и риском регрессий. Если польза не перевешивает — сократить или отложить изменение.
- Цель — работающий основной сценарий. Мелкие баги допустимы, если не мешают ему;
  находка не становится обязательной задачей. Явные требования сохраняют силу.
- Предпочитать локальные изменения; не перерабатывать соседний рабочий код без необходимости.

## Agent decisions

Следовать [working policy](workflows/execute-loop.md#working-policy).
Нерешённые существенные вопросы согласовывать с оператором; автономность действует
только в разрешённых границах. Не переспрашивать принятое и не считать молчание согласием.

## Working memory

Писать максимально компактно: факты, решения с необходимым обоснованием, открытые
вопросы и результаты проверок. Без воды, повторов, стенограмм и пустых разделов.
Обновлять канонический источник, ссылаться вместо копирования; сохранять ID задач и доказательства.

## Completion

Проверки соразмерны изменению и риску. Кратко сообщать результат, реальные проверки
и ограничения; не выдавать непроведённую проверку за успешную и не скрывать сбои.

## Flexible process

Глубина процесса определяется пользой. Оператор может пропускать этапы без оформления
исключений. Отсутствие формальных артефактов не блокирует работу; реальные зависимости
и решения вне полномочий останавливают только затронутую часть.

## Changes to these principles

Принятые изменения отражать в затронутых документах. Предметные правила хранить
в спецификациях. Явные указания оператора имеют приоритет над правилами фреймворка.
