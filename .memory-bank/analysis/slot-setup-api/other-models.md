# H3, Vidu Q4 и Gemini Omni — входы слота

Проверены публичные API-страницы и загруженные OpenAPI-схемы fal. Генерации не
запускались; фактическое сохранение лиц и композиции не проверено. Выводы о поведении
ReelMe ниже отделены от возможностей API. Матрица: [матрица слотов](../../../docs/slot-setup/matrix.md).

| Endpoint | Фото / персонажи | Промпт | Разрешения в задаче | Соотношения сторон API |
|---|---|---|---|---|
| `minimax/h3-max/recast` | `reference_image_urls`: 1–4; один файл на нового человека; Elements нет | Необязательный, ≤2000 символов | `768P`, `1080P` | Поля нет |
| `minimax/h3-max/reference-to-video` | `reference_image_urls`: максимум 9; общий предел image/video/audio references — 12; Elements нет | Обязательный, 1–50000; `Image 1` и далее | `768P`, `1080P` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `fal-ai/vidu/q4/reference-to-video` | До 12 `reference_image_urls`; предел указан в description, без `maxItems`; Elements нет | Обязательный, 1–5000; `[@reference_image_1]` и далее | `720p`, `1080p` | `16:9`, `9:16`, `4:3`, `3:4`, `1:1` |
| `google/gemini-omni-flash/v1.2/reference-to-video` | `image_urls`: максимум 10 (`maxItems`); Elements нет | Обязательный, ≤20000; пример использует `<IMAGE_REF_0>` и далее | `720p`, `1080p` | `16:9`, `9:16` |

Полные enum разрешений шире задачи: H3 Reference также `480P`; Vidu также `540p`,
`2K`, `4K`; Gemini также `360p`, `4k`. В UI показывается только запрошенная пара.
В H3 нельзя отправлять `720p` вместо `768P`: регистр и значение имеют значение.

## Факты и последствия для настройки

Recast сопоставляет отдельные фотографии новым людям; без инструкции — основным
людям исходного ролика слева направо. Видео: 5–30 секунд, каждый непрерывный план
не длиннее 15 секунд. В проверенной схеме нет пределов размера/FPS/пикселей/кодека
и нет `aspect_ratio`. Сохраняется звук исходного ролика. Один групповой снимок не
описан как способ заменить несколько людей. Для принятого UI рекомендуются 1/2
человека по одному кадру, без дополнительных фото сцены, с отключённым `3+`.
Исходный ролик должен соответствовать числу и порядку заменяемых людей.

H3 Reference допускает обычные изображения субъектов/стиля. Для выбранного пути
`reference_image_urls` потолок **9 фото, не 12**. Альтернативный
`reference_conditions` имеет `maxItems: 12`, но не доказывает разрешение 12 фото:
он предназначен для смешанного упорядоченного списка и несовместим с
`reference_*_urls`. Для KISS сохраняется существующий путь с девятью фотографиями.
`prompt_expansion_mode` обязателен; для ReelMe принят `disabled`. Длительность
0.92–15 секунд, результат может быть примерно на 0.7 секунды длиннее.
`1080P` описано как refinement из нативных 768P. Если передан `image_url`
первого кадра, выходное полотно следует ему; текущая схема ReelMe его не использует.

Vidu принимает PNG/JPEG/JPG/WebP, включая data URI; длительность 3–16 секунд.
Аудиореференсы имеют отдельный описанный максимум 3, но в этом изменении не нужны.
Число персонажей и число фото одного персонажа отдельными ограничениями не заданы.

Gemini принимает до десяти фото; длительность 3–15 секунд. Входные медиа идут
перед промптом в порядке списка. Схема также допускает три reference-видео до
15 секунд каждое; текущему сценарию P2V они не требуются. У `prompt` нет `minLength`,
но шаблон ReelMe непустой. Число людей и число ракурсов отдельно не ограничены схемой.

## Люди, ракурсы и группа

Для трёх P2V endpoint структура — плоский список. Распределение «эти четыре фото —
один человек, следующие четыре — другой» задаётся текстом, а не Elements. Это
предложение по составлению промпта, не подтверждённая гарантия качества.
Режим `3+` передаёт 1–4 групповых кадра обычными референсами; prompt описывает
тот же состав группы. Документация не задаёт гарантированного максимума лиц в
группе, поэтому UI не должен обещать, например, «8 персонажей» из лимита файлов.

Для H3 Reference при двух людях по четыре кадра остаётся одно дополнительное фото;
для Vidu — четыре; для Gemini — два. Эти расчёты предполагают только фото,
без дополнительных видео/аудио/первых/последних кадров.

## Принятый выбор разрешения и ориентации

- У P2V ориентацию можно явно отобразить в `aspect_ratio`: горизонтальная по
  умолчанию `16:9`, вертикальная `9:16`; остальные допустимые значения фильтровать
  по направлению. Квадрат `1:1` не входит в двухвариантный UI горизонталь/вертикаль.
- `adaptive` у H3 не фиксирует выбранное направление; для явного выбора следует
  отправлять конкретное соотношение. Если в будущем включить первый кадр, учитывать
  его приоритет над полотном результата, не обещать независимый crop.
- У Recast нет API-поля ориентации; по принятому решению направление определяется
  привязанным видео. UI показывает соответствующее исходнику значение и объясняет
  ограничение. Приложение не добавляет crop/upscale и не имитирует отсутствующие
  настройки API.
- Фактическая поддержка групповых идентичностей P2V не проверена генерацией;
  это ограничение проверки, а не причина изобретать числовой лимит людей.
