# Kling 4: ограничения для нового редактора слотов

Проверены публичные fal OpenAPI и официальные страницы; платные запросы и доступ
аккаунта не проверялись. Родительская [матрица](../../../docs/slot-setup/matrix.md).
Схема описывает допустимую форму запроса, но не доказывает качество сохранения лиц.

## Endpoints и выходное видео

| Endpoint | Resolution | Aspect ratio API | Длительность | Шаблон |
|---|---|---|---|---|
| `kling/v4/video-to-video/edit` | `720p`, `1080p` | `auto`, `16:9`, `9:16`, `1:1`, `21:9`; поле необязательно, без него следует исходному видео | 3–30 с; без duration — исходная | [edit](../../../public/slot-prompts/kling-v4-edit/people-1__photos-4__refs-0.md) |
| `kling/v4/flash/video-to-video` | Только `720p` | Поля нет; независимое изменение выходной ориентации этим API не подтверждено | 3–20 с; без duration — исходная | [flash edit](../../../public/slot-prompts/kling-v4-flash-edit/people-1__photos-4__refs-0.md) |
| `kling/v4/reference-to-video` | `720p`, `1080p` | `auto`, `16:9`, `9:16`, `1:1`, `21:9`; default `16:9` | 3–30 с, целое | [reference](../../../public/slot-prompts/kling-v4-reference/people-1__photos-4__refs-0.md) |
| `kling/v4/flash/reference-to-video` | Только `720p` | `auto`, `16:9`, `9:16`, `1:1`, `21:9`; default `16:9` | 3–20 с, целое | [flash reference](../../../public/slot-prompts/kling-v4-flash-reference/people-1__photos-4__refs-0.md) |

Для явной горизонтали использовать `16:9`, вертикали `9:16`; `auto` не гарантирует
выбранную ориентацию. `1:1` не относится ни к одной из двух ориентаций — продуктовый
выбор, показывать ли его. API full-моделей не поддерживает `768p`; Flash не принимает
`1080p`. Изменение текста промпта не заменяет отсутствующий параметр.

Источники строк: [full edit API](https://fal.ai/models/kling/v4/video-to-video/edit/api),
[Flash edit API](https://fal.ai/models/kling/v4/flash/video-to-video/api),
[full reference API](https://fal.ai/models/kling/v4/reference-to-video/api),
[Flash reference API](https://fal.ai/models/kling/v4/flash/reference-to-video/api).

## Фото, Elements, совместный бюджет

У всех четырёх схем `image_urls.maxItems=10`, `elements.maxItems=7`.
Изображение Element: `frontal_image_url` и до трёх `reference_image_urls`.
Описание последних говорит о 1–3 дополнительных видах, но JSON Schema не содержит
`minItems`, оба поля nullable и не входят в required. Поэтому два–четыре разных
снимка — документированный многовидовой путь; один frontal без дополнительных видов
проходит видимую структуру схемы, но принятие runtime-валидатором не доказано.
Не дублировать один JPEG, чтобы обойти это расхождение.

Обычные ссылки нумеруются `@Image1…`; Elements — `@Element1…` независимо от числа
внутренних видов. Индексы начинаются с 1. Вложенные снимки не надо вторично добавлять
в `image_urls`: это заняло бы обычные места и изменило номера остальных изображений.

[fal](https://fal.ai/kling-4) и
[Kling 4 User Guide](https://kling.ai/quickstart/kling-4-model-user-guide)
указывают общий предел 15 assets: изображения, видео, Elements и голоса вместе.
Поэтому 10 изображений + 7 Elements одновременно обещать нельзя.
Описание считает Element отдельным типом asset; точная серверная формула учёта
его вложенных фотографий публично не раскрыта. Прочтение «один Element = одна
единица, его ракурсы отдельно не вычитаются из image_urls» согласуется с моделью
входа, но требует проверки fal при спорных сочетаниях.

Для принятого scope без голосов, keyframes и дополнительных видео оператор выбрал
трактовку: `E ≤ 7`, `I ≤ 10`, `E + I + V ≤ 15`, где `V=1`
для V2V, `0` для P2V. При максимум двух индивидуальных Elements потолок 15 не
ограничивает 10 обычных refs. Это расчёт assets, а не обещание 18 независимых фото
во всех комбинациях. Общий предел 15 у Flash отдельно не повторён в fal-схеме;
для режима 1/2 людей он также не становится ограничивающим.

Дополнительный предел по числу физических фото внутри Elements не вводится.
Решение опирается на документацию, не на выполненный runtime-запрос; возможные
расхождения будут уточняться при отладке реальных вызовов.

Групповые фотографии можно передавать обычным `image_urls`; формального ограничения
на число лиц в изображении в этих схемах нет. Это основание для группового сценария
по форме входа, но не гарантия сохранения каждого лица. Все групповые ракурсы идут
в начало `image_urls`, затем дополнительные изображения; Elements для группы нет.

## Промпт и медиа

Во всех четырёх fal-схемах `prompt.maxLength=26000` символов. Full P2V принимает
`prompt` либо `multi_prompt`; для ReelMe достаточно одного prompt. Остальные три
endpoint требуют prompt. Источник V2V всегда `@Video1`. Индексы изображений и
Elements берутся из фактически собранного payload, а не из числа выбранных кадров.
Официальный Kling guide отдельно указывает предел 8000 tokens: это другая единица,
не замена лимита fal. Короткие предложенные шаблоны далеки от обоих пределов.

Фото: до 31 457 280 bytes (в UI fal «30 MB»), каждая сторона от 300 px,
отношение ширины к высоте 0.4–2.5. V2V исходник: до 314 572 800 bytes («300 MB»),
обе стороны 700–4553 px, ratio 0.4–2.5, FPS 23.9–60.05. Длительность исходника:
full 3–30 с, Flash 3–20 с (в x-fal верхний допуск +0.05 с).
Эти ограничения входа не являются перечнем поддерживаемых выходных ориентаций.

## Решения оператора и ограничения внедрения

- Индивидуальный Kling использует 2–4 разных фото на человека; один кадр отключён
  по решению оператора, без дублирования фото или перехода на ordinary-image путь.
  Это продуктовая граница на фоне неясности fal single-photo validation.
- Неподдерживаемые разрешения/ratio отключаются; upscale/crop не выполняется.
  Для Flash V2V доступная ориентация привязана к исходному ролику слота.
- Промпты заранее сформированы в отдельные `.md`: [полный каталог](../../../docs/slot-setup/prompt-catalog.md).
  Runtime выбирает готовый файл, без подстановок, описания слота и текстового AI.
  V2V сохраняет действие, камеру и окружение исходника; P2V предлагает нейтральный
  cinematic portrait с subtle natural movement. Identity/ref-блоки зависят от
  фактических входов; администратор может исправить итоговый текст.
- Групповой V2V: оператор должен выбрать ролик с подходящей группой/композицией;
  число людей `3+` само по себе не задаёт точного соответствия персонажей исходника.
- На странице fal Kling 4 присутствует «API coming soon», при этом API-страницы и
  схемы доступны. Считать доступ конкретного аккаунта непроверенным; не подменять
  endpoint другой моделью при ошибке доступности.
