# ReelMe — замысел продукта

## Decision

`proceed`: интервью преобразовано в [PRD](../prd.md) и [карту требований](../requirements.md).
Продуктовое поведение определено для проектирования; архитектура и спецификации
прорабатываются до кода. Текущая готовность — в [backbone](../spec-backbone.md).

## Замысел

Посетитель выбирает сюжет, фотографируется и получает по email видео с собой
в главной роли. Заказчик управляет предложением и архивом мероприятий; сотрудник
помогает подготовиться, а съёмку ведёт приложение. Следующий посетитель не ждёт
завершения предыдущей генерации.

## Решения, определяющие направление

- Один заказчик, одна установка, один посетитель в ролике; два режима и все согласованные
  модели обязательны. Приоритет — V2V MiniMax H3 Max Recast.
- Клиентский `reelme.html` обслуживает digiCamControl; скрипты и остальные экраны —
  наш сервер. Выбор локального origin нужен для обращения к камере без её CORS-настройки.
- Домен `reelme.natureonzoom.win`; планируемая VPS AlmaLinux / 4 ГБ RAM, на входе Caddy,
  хостинг ещё выбирается. Расчётная посещаемость — 100 посетителей в день мероприятия.
- Основной код — TypeScript: фронтенд Svelte 5, сервер Node.js / Fastify.
  SQLite хранит записи, медиа — диск VPS. Почтовый сервис — SMTP.BZ.
- Два аккаунта: оператор показывает результаты и просматривает архив, администратор
  настраивает слоты и управляет архивом, включая удаление. У съёмочной установки
  отдельный ключ; посетителю аккаунт не нужен. Подробные права — в PRD.
- Мероприятие — день по Новосибирску; номера начинаются заново ежедневно.
- KISS допускает дубль генерации при потере подтверждения fal; отдельная защита от него
  не требуется. После полученного ID наблюдается тот же запрос.
- Художественная приёмка AI-роликов исключена. Функциональные проверки сохраняются.
- Принципы и границы автономности — в [Constitution](../constitution.md).
  Пользовательские параметры, экраны, таймеры и сценарии ошибок принадлежат PRD.
