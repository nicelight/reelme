### Контекст проекта

Разрабатывается веб-платформа для автоматизированной фотосъёмки и последующей AI-генерации персонализированных видео.

На компьютере заказчика установлена Windows 11 Pro, к которой по USB подключена зеркальная камера Canon EOS 1100D.

Платформа предусматривает панель администратора с десятью видеослотами. Заказчик может загружать в каждый слот исходное видео, предназначенное для последующей AI-обработки. Клиент выбирает один из доступных слотов, после чего веб-приложение последовательно показывает ему 5–6 поз, сопровождая каждый этап звуковым обратным отсчётом и автоматической фотосъёмкой. Полученные фотографии отправляются на облачный сервер, где используются для замены человека в выбранном видео. Готовый результат доступен для просмотра, скачивания или получения через QR-код.

### Интеграция с камерой

В качестве готового программного интерфейса для взаимодействия с Canon рассматривается **digiCamControl** — бесплатное приложение с открытым исходным кодом и лицензией MIT.

Программа поддерживает Canon EOS 1100D и предоставляет встроенный HTTP-сервер, по умолчанию работающий на порту 5513.

Через HTTP-интерфейс доступны удалённый спуск затвора, получение информации о фотографиях, скачивание оригинальных JPEG и получение кадров Live View.

Примеры доступных HTTP-эндпоинтов:

- `http://localhost:5513/?CMD=Capture` — команда съёмки.
- `http://localhost:5513/filelist.json` — список фотографий текущей сессии.
- `http://localhost:5513/image/filename.jpg` — получение оригинального JPEG.
- `http://localhost:5513/liveview.jpg` — получение изображения Live View.

Команда съёмки и получение готового файла являются отдельными операциями. Поэтому готовность нового JPEG и его соответствие текущему кадру учитываются в логике веб-приложения.

Экспозиция преимущественно определяется самой камерой. Предполагается использование автоматических настроек ISO, выдержки, диафрагмы и баланса белого. Скорость автофокусировки и получения готового кадра зависит от камеры, объектива и условий освещения.

digiCamControl выступает исключительно посредником между USB-камерой и браузером. Вся бизнес-логика, пользовательский интерфейс, управление видеослотами и AI-обработка находятся в нашей веб-платформе.

### Особенность встроенного веб-сервера и обход CORS

При изучении исходного кода digiCamControl обнаружена полезная особенность: встроенный HTTP-сервер способен раздавать не только API управления камерой, но и обычные статические файлы, находящиеся в его каталоге `WebServer`.

Это позволяет разместить в данном каталоге небольшую HTML-страницу, выполняющую роль загрузчика основной веб-платформы.

Обычная схема, при которой пользователь открывает `https://our-platform.com`, а JavaScript обращается к `http://localhost:5513`, создаёт междоменные запросы. Встроенный сервер digiCamControl не предоставляет документированного механизма настройки CORS для произвольного внешнего сайта.

Альтернативная архитектура предполагает открытие приложения по локальному адресу:

`http://localhost:5513/reelme.html`

При этом HTML-страница загружает интерфейс и JavaScript с нашего облачного сервера.

Несмотря на внешнее расположение JavaScript-кода, он выполняется в контексте локальной страницы, origin которой — `http://localhost:5513`.

Следовательно, обращения вида:

`fetch('/?CMD=Capture')`

выполняются в пределах одного origin и не требуют разрешений CORS со стороны digiCamControl.

При загрузке JavaScript с облачного сервера существуют обычные браузерные ограничения: классические внешние скрипты могут подключаться через `<script src="...">`, тогда как ES-модули требуют соответствующих CORS-заголовков от сервера, распространяющего модули.

Аналогично обращения локально открытого приложения к нашему облачному API требуют разрешения origin `http://localhost:5513` на стороне облачного сервера.

Таким образом, **CORS устраняется именно в части взаимодействия с локальным API камеры**, а не отключается глобально.

### Эксплуатация и обновления

На компьютере заказчика постоянно работает digiCamControl с активированным HTTP-сервером. Программа поддерживает автоматический запуск вместе с Windows и работу в свёрнутом состоянии.

Пользователь взаимодействует исключительно с нашим веб-интерфейсом, доступным через ярлык на рабочем столе.

В интерфейсе предусмотрены три основных раздела: управление видеослотами, фотосъёмка и получение готовых видео.

Основной интерфейс, логика сценариев и настройки находятся в облаке. Локальная HTML-страница практически неизменна и выполняет роль точки входа. Это позволяет обновлять функциональность платформы без переустановки локального программного обеспечения.

Встроенный HTTP-сервер digiCamControl, согласно исходному коду, может прослушивать все сетевые интерфейсы Windows. Поэтому безопасность локального API и его недоступность посторонним устройствам являются отдельными эксплуатационными аспектами. Для конечного заказчика предполагается первоначальная автоматизированная настройка без необходимости самостоятельного администрирования Windows.

### Существующий рабочий процесс

У заказчика уже используется коммерческая DSLR Remote Pro, которая фотографирует человека, отправляет изображение на существующий сервер и получает обратно обработанную фотографию.

Этот процесс сохраняется без изменений.

Новая веб-платформа разрабатывается независимо от DSLR Remote Pro. При этом обе программы могут конкурировать за управление одной USB-камерой, поэтому одновременная работа с Canon не предполагается.

### Текущий статус решения

Использование digiCamControl является выбранным направлением интеграции, но ещё не подтверждено практическими испытаниями на конкретной связке Canon EOS 1100D и Windows 11 Pro.

Работоспособность удалённой съёмки, получения оригинальных JPEG, стабильность последовательной фотосъёмки и использование собственного HTML-загрузчика через встроенный веб-сервер пока рассматриваются как технически обоснованные, но экспериментально не проверенные возможности.

Основная архитектурная идея заключается в **полном отделении логики веб-платформы от программного обеспечения управления камерой**. digiCamControl предоставляет готовый локальный HTTP-интерфейс, тогда как вся функциональность конечного продукта реализуется независимо от него.
