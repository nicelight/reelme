# Пустой ответ digiCamControl на запрос списка файлов после съёмки

20 ноября 2026 года на установке с Canon EOS 1100D и digiCamControl 2.1.7.0 ReelMe показал «Не удалось получить кадр», код `c40f0ed8`. JPEG уже лежал в папке сессии. Запрос списка файлов вернул пустое тело, разбор JSON завершился ошибкой, и приложение остановилось до загрузки оригинала. После нажатия «Повторить» ReelMe принял тот же кадр.

## Хронология

Время Новосибирска (UTC+7). Сопоставлены `app.log` digiCamControl и обе попытки в таблице `capture_reports` на `nskserver` по префиксу `case_id`.

| Время | Источник | Наблюдение |
|---|---|---|
| 22:04:47.983 | ReelMe | Отправлена команда `LiveView_Capture`. digiCamControl зарегистрировал её в 22:04:47.988. |
| 22:04:50.589 | digiCamControl | `Photo transfer done.` — передача снимка с камеры завершилась. |
| 22:04:51.085 | digiCamControl | `Web server error`, затем `System.NullReferenceException` в `WebServerModule.HandleRequest` при обработке `FileItem`. |
| В тот же момент | ReelMe | Седьмой опрос `/filelist.json` после спуска вернул HTTP 200, `text/html` и 0 байт. Отчёт зафиксировал `stage=poll`, `phase=parse`, `Invalid JSON`. Попытка завершилась через 3 119 мс при таймауте 30 000 мс. |
| 22:05:55.177 | ReelMe | Нажатие «Повторить» запустило `resume`. Первый запрос списка вернул JSON. Приложение скачало 9 174 413 байт, проверило и декодировало JPEG. Весь повтор занял 379 мс без нового спуска. |

Такое же исключение веб-сервера встречается после соседних снимков. Журнал digiCamControl не указывает, какое поле оказалось пустым. Вывод о причине ошибки на экране подтверждён для случая `c40f0ed8`. [Порядок поиска отчётов по коду случая](../../docs/MANUAL.md#диагностика-захвата-кадра).

## Строки для следующего разбора

- Для каждого кадра сохранить время с миллисекундами и строки с префиксами `Window command received :LiveView_Capture` или `Window command received :Capture`, `EOS capture start`, `EOS capture end`, `Picture taken event received`, `Photo transfer begin`, `Photo transfer done.`, `Web server error`. Для первого исключения сохранить полный стек, для одинаковых повторов — время, тип и строку с `FileItem`.
- Если запись об окончании передачи отсутствует, сохранить промежуточные шаги от `Pointer file transfer started` до `Camera.ResumeLiveview()`. При перезапуске важны также `Application starting`, `Unable to start webserver`, `Unable to stop liveview` и `Window command received :All_Close`.
- В выборке для ошибки списка можно пропускать `No translation for:`, `Window command received :Zoom_Image_Fit`, `Window command received :RefreshDisplay`, `Logo file not found`, `Loading plugin dll` и `Init :`.

## Обработка пустого ответа в ReelMe

После остановки активного опроса Live View приложение выдерживает 200 мс перед первым запросом к digiCamControl для получения кадра.

Если после спуска опрос `/filelist.json` получил HTTP 200 с телом длиной 0 байт, ReelMe повторяет запрос через 300 мс. Если нового JPEG по-прежнему нет, следующий запрос отправляется через 1 секунду после ответа. На любом из этих шагов появившийся JPEG сразу скачивается. Если обе проверки закончились без нового JPEG, установка предлагает «Повторить» для того же кадра. На все запросы одной попытки действует общий таймаут 30 секунд. [Адаптер камеры](../../src/client/capture/camera.ts).

Корректный JSON-список без нового кадра до первого пустого HTTP-ответа означает, что камера ещё сохраняет снимок. В этом случае ReelMe продолжает штатный опрос. При автоматических и ручных повторах исходный список сохраняется, команда спуска отправляется один раз.

20 ноября 2026 в 23:01 по Новосибирску на `nskserver` выпущен первый вариант с интервалами 500 и 1000 мс. В 23:21 выпущен `20261120T161758Z-preview-delay` с паузой 200 мс после Live View и интервалами 300 и 1000 мс. Публичный загрузчик отдаёт проверенный модуль `capture-DGacQpWl.js`. Тайминги проверены с управляемыми ответами камеры. Влияние паузы на частоту пустых ответов на Canon ещё предстоит измерить.
